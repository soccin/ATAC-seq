# ATAC-seq — Issues

IRIS / Slurm only, as of v1.5.0. Compiled 2026-10-09 from a review of the
port and from probe jobs run on the cluster that day.

- Architecture and conventions: `CLAUDE.md`
- What changed, per release: `CHANGELOG.md`
- How the port was done, flag translation, resource choices:
  `docs/SLURM_PORT.md`
- Measured cluster facts (shared with PEMapper):
  `Proj_18143_B/PEMapper/docs/IRIS_CLUSTER_INFO.md`

Labels: type (`bug`, `risk`, `docs`, `enhancement`, `cleanup`), priority,
`port-gap` where the work belonged in the port and was not done, and
`pre-port` where the defect existed under LSF and was carried over. Line
numbers refer to v1.5.0.

Order of work: by the priority label, `medium` before `low`.

## Open

**#7 Unsupported genomes are not rejected up front** · `bug` `medium`
`pre-port` — `pipe.sh` rejects only `unknown`. Detected tags such as
`hg19`, `b37_dmp` or `GRCh37-lite` pass, and then every POST job fails.
`mm10` is worse: stages 1 to 6 succeed, stage 7 (`computeTSSEnrich.sh`)
fails because `R/TSSEnrich/lib/` has only `b37` and `b38` files, and
`bCheck` aborts before anything is staged into `atacSeq/`. Only the first
BAM is checked, so mixed builds are not detected either. Fix: one
supported-genome check in `pipe.sh` over all BAMs. For mm10, add the TSS
files, or skip stage 7 with a warning when the files are missing.

**#8 `deliverResults.sh` not ported** · `enhancement` `medium` — Still
uses `/ifs/res/seq/pi/invest` and `~/Code/BIC/Delivery/Version2j/...`.
Delivery is manual until the script targets the IRIS delivery area.
When porting, check its file patterns against what
`R/diffAnalysisPairwise.R` writes now (`*DiffPeaksEdgeR_V4.xlsx`,
`*DiffPeaks_V4.pdf`).

**#9 `~/bin/picard` is not sized from the Slurm job** · `enhancement`
`medium` — The wrapper is used as-is by POST. It sets a fixed `-Xmx24g`
whatever the job's `--mem` (POST asks for 32G to fit it). It puts
`TMP_DIR` on the shared `/scratch/core001/bic/socci/PICARD/$$` and never
removes that directory (101 empty directories there on 2026-10-09). Under
Slurm it also creates an empty `SLM/` in every analysis directory.
PEMapper already solved the first two: `TMP_DIR=/localscratch`, and the
heap derived from `SLURM_MEM_PER_NODE` in `bin/picardJvm.sh`. Decide
whether to fix the shared wrapper in `~/bin` or to reuse the PEMapper
approach inside this repo.

**#11 Scratch directories are left behind on failure** · `cleanup` `low`
— `postMapBamProcessing_ATACSeq.sh` and `callPeaks_ATACSeq.sh` remove
their `$TDIR` under `/scratch/core001/bic/$USER/ATACSeq` only on success.
Add `trap 'rm -rf "$TDIR"' EXIT` after creating it.

**#12 A BAM without an `@RG SM:` tag writes into `out/`** · `bug` `low`
`pre-port` — `postMapBamProcessing_ATACSeq.sh` takes `SID` from the first
`SM:` tag. If there is none, `SID` is empty, the output becomes
`out/_postProcess.bam`, and samples processed in parallel overwrite each
other. Exit with an error when `SID` is empty. `pipe.sh` now checks every
BAM for an SM tag, and for duplicates, before submitting, so this is
left only for standalone runs of the stage script.

**#13 `makeBigWigFromBEDZ.sh` scale-factor branch reads the wrong
argument** · `bug` `low` `pre-port` — With three arguments it sets
`scaleFactor=$2`, which is the BED path; it should be `$3`. `pipe.sh`
always passes two arguments, so the 10M-read normalization used in
production is not affected.

**#14 `featureCounts -Q 10` ignores `-q MAPQ`** · `bug` `low` `pre-port`
— The Count stage hard-codes `-Q 10`. With `-q` below 10, the count
matrix still uses 10. Pass `$MAPQ`.

**#15 Small defects in `pipe.sh`** · `cleanup` `low` `pre-port` —
- The manifest step leaves `mapid`, `sid` and `gid` in the analysis
  directory.
- `git describe` has no `--dirty`, so the logged version does not show
  uncommitted edits to the checkout.

**#25 `MESSAGE` is empty when a stage fails** · `enhancement` `low` —
When `bCheck` aborts the run, `00.RUNSTATUS.txt` records `STAGE` and
`RC` only. Have `bCheck` set `RUN_MESSAGE` to the failed job ids and
their `sacct` states, so the status file says which sample failed.

**#26 The trap may not run during the R reports or staging** · `risk`
`low` — `bSync` waits in the background so a SIGTERM reaches the trap at
once, but `plotINSStats.R`, `analyzeATAC.R` and the `cp` into `atacSeq/`
run in the foreground. A `scancel` or time limit there leaves
`STATUS=RUNNING`. `checkRun.sh` still reports `FAILED` from `sacct`, and
no stage jobs are left to cancel at that point. Fix if needed: run these
in the background and `wait`, as `bSync` does.

**#27 Early exits write no status file** · `enhancement` `low` — A bad
option, `usage`, the `SBATCH_SCRIPT_DIR` check and the venv check exit
before the `EXIT` trap is installed. `checkRun.sh` reports `NONE`; the
reason is only in the control log. Fix: install the trap and write
`STATUS=FAILED` with a `MESSAGE` before these checks. Leave out
`checkPreviousRun`: a run it refuses must not write the status file,
which belongs to the earlier run.

**#28 Old runs cannot be classified once `sacct` forgets the control job**
· `enhancement` `low` — Stage logs end with `#ATAC_EXIT=<rc>`, but the
control log has no trailer. When a control job died with
`STATUS=RUNNING` and `sacct` no longer has it, `checkRun.sh` cannot tell
a dead run from a live one. Fix: have the `EXIT` trap print
`#ATAC_EXIT=<rc>` to the control log, and have `checkRun.sh` read it
when `sacct` has no record.

**#29 The deliverables check is narrow** · `enhancement` `low` — It does
not check the `.bai` files written by the Index stage, the featureCounts
`.summary`, or that `sampleManifest.csv` has one row per sample. The
narrowPeak file is checked with `-e`, so an empty one passes. Decide
whether zero peaks is a failure; if so, use `-s`.

**#30 `checkRun.sh` cannot write its report to a file** · `enhancement`
`low` — PEMapper's `checkRun.sh` takes `-o FILE`. Add the same option so
the report can be kept with the run.

**#31 CPU requests are larger than the use** · `cleanup` `low` — On the
full-size run (`docs/SLURM_PORT.md`, "Walltime classes") TotalCPU/Elapsed
was about 1.2 for CALLP (`-n 3`), 1.0 for TSSE (`-n 2`) and 0.75 for
Count (`-n 10`, `featureCounts -T 10`; I/O bound across the BAMs). Fewer
cores would schedule more easily on busy nodes. Check whether MACS2 or
featureCounts slow down before lowering them.
