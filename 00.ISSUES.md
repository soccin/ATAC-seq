Labels: type (`bug`, `risk`, `docs`, `enhancement`, `cleanup`), priority,
`port-gap` where the work belonged in the port and was not done, and

## Open

**#1 `deliverResults.sh` not ported** (was #8) · `enhancement` `medium`
— Still uses `/ifs/res/seq/pi/invest` and
`~/Code/BIC/Delivery/Version2j/...`. Delivery is manual until the script
targets the IRIS delivery area. When porting, check its file patterns
against what `R/diffAnalysisPairwise.R` writes now
(`*DiffPeaksEdgeR_V4.xlsx`, `*DiffPeaks_V4.pdf`), and the
`*___MITO.txt` files in `atacSeq/metrics` (new in v2.0.0).

**#2 `~/bin/picard` is not sized from the Slurm job** (was #9) ·
`enhancement` `medium` — The wrapper is used as-is by POST. It sets a
fixed `-Xmx24g` whatever the job's `--mem` (POST asks for 32G to fit it).
It puts `TMP_DIR` on the shared `/scratch/core001/bic/socci/PICARD/$$`
and never removes that directory (101 empty directories there on
2026-10-09). Under Slurm it also creates an empty `SLM/` in every
analysis directory. PEMapper already solved the first two:
`TMP_DIR=/localscratch`, and the heap derived from `SLURM_MEM_PER_NODE`
in `bin/picardJvm.sh`. Decide whether to fix the shared wrapper in
`~/bin` or to reuse the PEMapper approach inside this repo.

**#3 Scratch directories are left behind on failure** (was #11) ·
`cleanup` `low` — `postMapBamProcessing_ATACSeq.sh` and
`callPeaks_ATACSeq.sh` remove their `$TDIR` under
`/scratch/core001/bic/$USER/ATACSeq` only on success. Add
`trap 'rm -rf "$TDIR"' EXIT` after creating it.

**#4 A BAM without an `@RG SM:` tag writes into `out/`** (was #12) ·
`bug` `low` `pre-port` — `postMapBamProcessing_ATACSeq.sh` takes `SID`
from the first `SM:` tag. If there is none, `SID` is empty, the output
becomes `out/_postProcess.bam`, and samples processed in parallel
overwrite each other. Exit with an error when `SID` is empty. `pipe.sh`
now checks every BAM for an SM tag, and for duplicates, before
submitting, so this is left only for standalone runs of the stage
script.

**#5 `makeBigWigFromBEDZ.sh` scale-factor branch reads the wrong
argument** (was #13) · `bug` `low` `pre-port` — With three arguments it
sets `scaleFactor=$2`, which is the BED path; it should be `$3`.
`pipe.sh` always passes two arguments, so the 10M-read normalization used
in production is not affected.

**#6 Small defects in `pipe.sh`** (was #15) · `cleanup` `low` `pre-port`
—
- The manifest step leaves `mapid`, `sid` and `gid` in the analysis
  directory.
- `git describe` has no `--dirty`, so the logged version does not show
  uncommitted edits to the checkout.

**#8 The trap may not run during the R reports or staging** (was #26) ·
`risk` `low` — `bSync` waits in the background so a SIGTERM reaches the
trap at once, but `plotINSStats.R`, `analyzeATAC.R` and the `cp` into
`atacSeq/` run in the foreground. A `scancel` or time limit there leaves
`STATUS=RUNNING`. `checkRun.sh` still reports `FAILED` from `sacct`, and
no stage jobs are left to cancel at that point. Fix if needed: run these
in the background and `wait`, as `bSync` does.

**#9 Early exits write no status file** (was #27) · `enhancement` `low`
— A bad option, `usage`, the `SBATCH_SCRIPT_DIR` check and the venv
check exit before the `EXIT` trap is installed. `checkRun.sh` reports
`NONE`; the reason is only in the control log. Fix: install the trap and
write `STATUS=FAILED` with a `MESSAGE` before these checks. Leave out
`checkPreviousRun`: a run it refuses must not write the status file,
which belongs to the earlier run.

**#10 Old runs cannot be classified once `sacct` forgets the control
job** (was #28) · `enhancement` `low` — Stage logs end with
`#ATAC_EXIT=<rc>`, but the control log has no trailer. When a control
job died with `STATUS=RUNNING` and `sacct` no longer has it,
`checkRun.sh` cannot tell a dead run from a live one. Fix: have the
`EXIT` trap print `#ATAC_EXIT=<rc>` to the control log, and have
`checkRun.sh` read it when `sacct` has no record.

**#11 The deliverables check is narrow** (was #29) · `enhancement` `low`
— It does not check the `.bai` files written by the Index stage, or
that `sampleManifest.csv` has one row per sample. (The featureCounts
`.summary` and the count-check report are checked since
`fix/featurecounts`.) The narrowPeak file is checked with `-e`, so an empty one passes.
Decide whether zero peaks is a failure; if so, use `-s`.

**#12 `checkRun.sh` cannot write its report to a file** (was #30) ·
`enhancement` `low` — PEMapper's `checkRun.sh` takes `-o FILE`. Add the
same option so the report can be kept with the run.

**#13 CPU requests are larger than the use** (was #31) · `cleanup` `low`
— On the full-size runs (`docs/SLURM_PORT.md`, "Walltime classes")
TotalCPU/Elapsed was about 1.2 for CALLP (`-n 3`) and 1.0 for TSSE
(`-n 2`). Fewer cores would schedule more easily on busy nodes. Check
whether MACS2 slows down before lowering CALLP.

**#14 No mm10 run on v2.0.0** · `risk` `medium` — hg38 and b37 have
been run on this version (`docs/SLURM_PORT.md`, "Validation"). mm10 was
checked only with header-only BAMs (detection, `GENOMES.tsv`, the file
checks in `pipe.sh`), which stop at the `@RG SM` check before any job
runs. Untested for mm10: the genome file without `chrM` in POST, BW and
CALLP, the `___MITO.txt` metric, TSSE with the new mm10 files (check
`pct_tss_used`), and the mm10 annotation in `diffAnalysisPairwise.R`.
No mm10 ATAC run was found on IRIS. The ChIP-seq test set (Proj_16852,
8 mm10 Cut&Run BAMs, `00.JUNO/ThompsonC/NgC3/Proj_16852`) can test the
mechanics; an mm10 ATAC project is needed to judge the TSS score.
Downsample with `PortATACseq/Ports/PEMapper/bin/downsampleBam.sh`.

**#16 Setup failures with an empty or wrong status record** · `bug`
`low` — Found with header-only BAMs on 2026-10-11.
- The two `@RG SM` checks in `pipe.sh` (no SM tag; one SM tag on two
  BAMs) exit without setting `RUN_MESSAGE`, so `MESSAGE` is empty; the
  reason is only in the control log. Set it as the genome checks do.
- `GENOME=` is written even when the genome checks fail: the
  unsupported tag (`GENOME=hg19`), or the first BAM's tag when a later
  BAM differs or cannot be read. ChIP-seq sets `GENOME` only after every
  check has passed; do the same.

**#17 Check A failure does not name the sample** · `enhancement` `low`
— When Check A fails, `bin/countPeaks.sh` writes `FATAL ERROR: Check A
failed on peaks_raw_fcCounts.txt.summary`, so `MESSAGE` does not say
which sample. ChIP-seq's copy puts the first failing line of
`checkCounts.sh` into the FATAL line; take that change (the rest of
ChIP's copy is its `--single-end` option).

**#18 Genome checks that ChIP-seq has and ATAC does not** ·
`enhancement` `low`
- ChIP's `pipe.sh` checks that every contig of
  `lib/genomes/<GENOME>.genome` is in every BAM header with the same
  length. That catches a header md5 mapped to the wrong tag, or a
  genome file that does not match the data. ATAC trusts the md5.
- `bin/genomeInfo.sh` differs between the repos: ChIP's has `--tags`
  and a `GENOME_FILE` field. Only `getGenomeBuildBAM.sh` must be
  identical, but sharing one `genomeInfo.sh` would keep the two from
  drifting. ATAC's table has `MITO` and no `HOMER`, so the script, not
  the table, would be shared.
